# Migration plan: dsh 0.1.3-alpha.2+ support (assistant-stream seam) with back-compat to ≤0.1.2-rc.1

- Date: 2026-09-19
- Status: implementing (branch `feat/dsh-0.1.3-plus-support`)
- Scope: this package (`dsh-acp-enhanced`) adapts to DeepSeek Harness
  `0.1.3-alpha.2` … `0.1.6-alpha.2` while staying loadable and correct on every
  harness generation from `0.1.0-rc.6` through `0.1.6-alpha.2`.

## 1. Background

Since the `0.1.2-rc.1` pin (2026-09-03) the harness shipped six releases:

| Version | Date | `assistant/chunk` session event | `agent/assistant-stream` Cordis event |
| --- | --- | --- | --- |
| 0.1.2-rc.1 (current pin) | 2026-09-03 | yes | no |
| 0.1.3-alpha.2 | 2026-09-07 | **removed — boundary** | yes |
| 0.1.5-alpha.1 / .2 | 2026-09-08/09 | no | yes |
| 0.1.5-rc.1 / rc.2 (`latest`) | 2026-09-10 | no | yes |
| 0.1.6-alpha.1 / .2 (`alpha`) | 2026-09-15/17 | no | yes |

`0.1.3-alpha.2` deleted the persisted `assistant/chunk` session event this
bridge's block-level streaming is built on, and replaced it with a
process-local, agent-scoped Cordis dispatch: `agent/assistant-stream` carries
one attempt's ordered `start` / `chunk` / `end` frames
(`dsh-agent-loop@0.1.6-alpha.2/lib/index.js:1029-1031`, frame type in
`dsh-agent/lib/types/runtime-types.d.ts:107-137`). The durable settlement is now
one `assistant/message` **or** `assistant/attempt` session event carrying the
whole compact stream in its `stream` field.

Without an adaptation the bridge loses, on every `≥0.1.3-alpha.2` host, its two
headline features — block-level streaming and `streamDeltas` token streaming —
and the reply only reaches the client when the message commits.

### 1.1 Link-time surface is intact (probed)

A scratch install of both `0.1.5-rc.2` and `0.1.6-alpha.2` families (bridge deps
+ probe package, the bridge imported from that resolution root) passes on both.
Every static import still resolves: `installModelSelection` (dsh-agent),
`defineTool` (dsh-tools), `SessionId` (dsh-session), `createUserMessage` /
`errorChain` / `ReasoningEffortId` (dsh-llm), `renderSkillContent` (dsh-skill),
and the `dsh-agent-presets` namespace import.

Runtime seams verified unchanged by source diff:

| API | 0.1.2-rc.1 | 0.1.5-rc.2 / 0.1.6-alpha.2 |
| --- | --- | --- |
| `permissionPresets.permissionState(session)` / `current(session)` | present | present (0.1.6 adds `AUTO_PRESET`, additive) |
| `user-questions/request` waterfall | present | byte-identical |
| `Session.snapshotEvents()` / `ownEvents()` / `eventAt()` | present | present |
| `AgentRegistry.create/resume` | present | present |
| `StreamChunk` vocabulary (`block-start`/`text-delta`/`reasoning-delta`/`block-end`/`usage`/`finish`/`tool-call-delta`) | present | **unchanged** |

So the break is behavioral, not a link-time failure — unlike the 0.1.2-alpha
migration, no import discipline change is needed.

### 1.2 Runtime breaks the link probe cannot see

Booting a real profile on `0.1.5-rc.2` (the keyless smoke) surfaced a second,
independent break: **the persistence service surface was redesigned**.

| API | ≤ 0.1.2-rc.1 | ≥ 0.1.5-rc.2 | Bridge before |
| --- | --- | --- | --- |
| `sessionPersistence.list()` | `SessionHeader[]` (`jsonl.list()` mapped `artifact.header`) | `SessionPersistenceSnapshot[]` → `{header, revision, sizeBytes?}` | treated each entry as a header → `new Date(undefined).toISOString()` → **`session/list` threw `Invalid time value`**, `session/delete` matched nothing |
| `sessionPersistence.load(id)` | `→ {meta, events}` | **removed**; handle API instead | `persistedFactsOf` silently returned `undefined` (its `try/catch`) |
| `sessionPersistence.readRaw(id)` | present when `supportsRawArtifacts === true` | **removed** (no `supportsRawArtifacts`) | stored titles stopped resolving |
| `open(id, access)` | absent | `→ handle {header, read(), close()}` | unused |

The official `dsh-session-query@0.1.5-rc.2` unwraps the same way
(`.map((snapshot) => snapshot.header)`), which confirms the intended read.

## 2. Architecture decisions

### 2.1 Two live streaming seams, one handler

`handleChunk(record, event)` already consumes exactly the `StreamChunk`
vocabulary the new frames carry, so the new seam reuses it verbatim:

- legacy (`≤0.1.2-rc.1`): `session/event` of type `assistant/chunk` → `handleChunk(record, event)`.
- frames (`≥0.1.3-alpha.2`): `agent/assistant-stream` with `frame.type === 'chunk'` → `handleChunk(record, { data: { chunk: frame.chunk, turn: frame.turn, step: frame.step } })`.

The synthetic `data.turn` / `data.step` matter only for `emitUsage`'s `_meta`,
which reads them from the event.

Root-context delivery of the agent-scoped dispatch is established two ways: the
official ACP bridge itself registers agent-scoped listeners at root
(`ctx.on("agent/inbox/claimed", ({ agent, … }) => …)`,
`dsh-acp@0.1.6-alpha.2/lib/index.js:1106`), and this bridge's existing
`ctx.on('user-questions/request', …)` receives the same `scopeTarget(agent, agent)`
carrier (verified on the new host in the 2026-09-01 migration, §6.8).

### 2.2 Per-step seam latch

A host that carried both seams would stream every block twice. The record gets a
per-step `streamSeam` latch (`'legacy' | 'frames' | undefined`): the first seam
to deliver for a step claims it, the other is dropped, and `resetDeltaStreaming`
(already run on every `step/start`) clears it with the rest of the per-step
state. No shipped host emits both; the latch exists so a future one cannot
double-deliver.

### 2.3 The `assistant/message` fallback stays as the safety net

PR #3's `emitMessageFallback` (already on this branch) forwards the committed
message whenever a step put no text on the wire. It becomes the third tier:
legacy seam → frames seam → committed message. It also covers `≥0.1.3-alpha.2`
hosts where a frame was dropped, and any future host that removes both live
seams. Its README/comment framing is corrected: it restores *delivery*, not
streaming.

### 2.4 One-shot base rows move into presets

`dsh-base@0.1.6-alpha.2` changed its row set; the bridge's bundle patch mirrors
the official web-app patch ("model-facing rows are owned by the agent-preset
realm"). Diff of row ids vs `0.1.2-rc.1`:

- added: `image-offload`, `mcp-resources`, `plugin-manager`, `ptc-runtime`, `tool-plugin-manager`, `workflow-ptc`
- removed: `tool-str-replace-editor`, `workflow-worker-thread`

The shipped `standard` preset now owns `workflow-ptc` and `tool-plugin-manager`
(`dsh-agent-presets@0.1.6-alpha.2/presets/standard/agent.cordis.yml`), and the
official web-app patch disables both at base level. The bridge adds both to its
disable list. It keeps its existing `workflow-worker-thread` /
`tool-str-replace-editor` entries rather than dropping them: the patch applier
warns-and-skips an id it cannot find (`dsh-app-boot` `applyEntryPatches`:
"A patch that matches nothing warns and is skipped"), so one version-agnostic
list stays correct on ≤ 0.1.2-rc.1 hosts where those rows still exist.

### 2.5 Persistence: probe the service instance, not the generation

Three helpers in `lib/index.js` absorb the persistence redesign of §1.2:

- `storedSessionHeaders(persistence)` — `list()` then `entry?.header ?? entry`,
  which is exactly what `dsh-session-query` does on the new generation and a
  no-op on the old one (entries are already headers).
- `loadStoredSession(persistence, id)` — `load()` when present, else
  `open(id, 'read')` → `handle.read()` → `handle.close()`.
- `readStoredTitle` — keeps the raw-artifact fast path when
  `supportsRawArtifacts === true` and `readRaw` exists, and otherwise bounds the
  read with `stat(id).sizeBytes` before loading the log through a handle.

`session/delete` additionally guards `locate`, which is a JSONL-backend method
rather than part of the abstract service.

## 5. Risks and rollback

- `agent/assistant-stream` is documented as process-local presentation data, not
  a stable public API — the same class as the `assistant/chunk` event it
  replaces, and the only way to keep the package's differentiator. The fallback
  keeps correctness if it changes again.
- The frames seam must never be the only text path: `emitMessageFallback`
  remains the safety net.
- The persistence helpers probe the *service instance*, so a future backend that
  offers neither `load` nor `open` degrades title/preset-from-disk reads to
  `undefined` rather than throwing (the pre-existing `try/catch` behaviour).
- Rollback: `git checkout main`; the isolated home is additive and untouched by
  the code change.

## 6. Implementation log

1. **The break is not one seam.** The link-time probe passes on both new
   generations, so `compat-check` alone would have declared victory. Booting a
   real profile found the persistence redesign (§1.2): `session/list` threw
   `Invalid time value` and `session/delete` silently matched nothing, both
   because `list()`'s contract changed from `SessionHeader[]` to
   `SessionPersistenceSnapshot[]`. Lesson recorded in §2.5: bump
   `scripts/acp-smoke-keyless.mjs`'s CLI across the generations in CI, because
   only a boot exercises the service surface.
2. **A bare CI profile cannot boot 0.1.2-alpha+ at all.** The shipped `standard`
   preset requires `subagent-model-selection-settings` in the Host scope, which
   only `scripts/init-acp-home.sh`'s user-layer row provides — a fresh
   `dsh plugin add link:` profile fails `session/new` with
   "`modelSelectionSettings` requires … in the Host scope". The smoke now seeds
   that row itself (mirroring the bootstrap, generation-gated by
   `dsh --version`) so the CI matrix can run on the new CLI.
3. **`dsh --version` rides the release line in the patch digit.** 0.1.5-rc.2's
   minor digit is `1`; the generation gate must read the third component, not
   the second.
4. **PR #3's test could not fail where it runs.** CI installs `0.1.0-rc.6`
   (which still streams through `assistant/chunk`), so the fallback was never
   exercised. The test now captures `ACP_DEBUG` stderr and asserts a live seam
   fired — on `0.1.5-rc.2` that is `agent/assistant-stream frame=chunk`, on
   `0.1.1-rc.2` it is `assistant/chunk`.
5. **`/model lists the catalog` is environment-sensitive.** The smoke asserts
   `deepseek-v4-flash`; a home whose `settings.yaml` pins `deepseek-flash` (as
   the developer's does) fails that assertion for reasons unrelated to the
   bridge. A fresh home passes. Left as-is; noted here so the next person does
   not chase it.
6. **The `command-goal` "gap" is a generation asymmetry, not an oversight.**
   Confirmed empirically: a `minimal` session on 0.1.5-rc.2 still advertises
   `goal`, because the base row is not disabled. But the old standard preset
   (`/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/config/agent-presets/
   standard/agent.cordis.yml` on 0.1.1-rc.2) has no `command-goal` row, so
   disabling the base row would strip `/goal` from every legacy host. The patch
   comment now records this instead of claiming a completeness it does not have
   (see §7).

## 7. Follow-ups (out of scope here)

- **`command-goal` is intentionally not disabled, and must not be.** The patch
  comment used to claim every model-facing base row a preset owns is disabled
  here; `command-goal` is the exception. The shipped `standard` preset only
  started owning that row in 0.1.2-rc.1 — on ≤ 0.1.1-rc.2 the base row is
  `/goal`'s only provider — so disabling it would delete the command on legacy
  hosts. `!!js` cannot branch on the harness generation (it evaluates with
  `with (ctx)` over the loader context + globals, with no version available), so
  the disable cannot be made conditional in a static patch. Accepted
  consequence: on ≥ 0.1.2 a `minimal`/`code` session still advertises `/goal`
  from the base layer. The comment and this entry exist so nobody "fixes" it
  into a legacy regression. A bridge-side filter (omit the command from
  `available_commands_update` when the session's preset does not own it) is the
  only way to close the cosmetic gap; not attempted.
- `image-offload` (`dsh-compaction-image-offload`, added by 0.1.6) sits at base
  level and is not owned by any shipped preset; the web-app patch leaves it
  enabled too, so this bridge matches the official composition. Revisit if the
  presets ever take it over.
- `scripts/init-acp-home.sh` still hard-excludes `dsh-mnemon`; re-check whether
  it supports the 0.1.6 line.
